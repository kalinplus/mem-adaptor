# M5：完整 OKF 与 UMP Writer（已确认、已实现）

用户已确认三项推荐：保守 kind 映射、正文首行标题、缺失创建时刻时使用明确标注的目标迁移创建时刻。
用户也已确认 §5 推荐的完整目标哈希、共享产物审批绑定与目标字段映射契约，已完成合成验收。

M4 已完成合成验收，62 个测试通过。M5 不读取真实记忆，不调用模型，不改变审批与回执链。
字段依据已核对的 OKF（Open Knowledge Format，开放知识格式）约定，
以及 UMP（Universal Memory Protocol，通用记忆协议）1.0 的官方 JSON Schema。

## 1. UMP 类别映射

推荐保守映射，不根据正文或日期猜测：

| 源类别 | UMP kind |
|---|---|
| profile | identity |
| preference | semantic |
| instruction | procedural |
| project / tool / project_doc | semantic |
| 已明确属于 UMP 五种类别 | 原类别 |
| 未知或缺失 | semantic，明确标记默认映射 |

原 `source_kind` 与 `dna_class` 保留在目标 metadata，回读可恢复。
项目背景可能是长期事实，所以默认不映射成 working（临时工作上下文）。

可选路径：

1. **保守映射（推荐）**：只有明确的身份/程序性要求采用对应 kind，其余常规事实为 semantic。
2. **project → working**：更贴近短期项目上下文，但可能把长期背景误标成临时信息。
3. **全部 semantic**：最简单，但目标侧无法按身份/程序性记忆分类。

## 2. OKF 标题

推荐取正文首个非空行，去掉标题标记后按 Unicode 字符截断至 80 字；
正文不变，空正文使用 `Memory <canonical_id>`。不生成 description，不调用模型。
原始 title/name/description metadata 继续保留，不被派生展示标题覆盖。

可选路径：

1. **正文首行（推荐，与实现计划一致）**：确定性、无远程调用，适合统一显示。
2. **优先原始标题**：标题更贴近来源，但需为三个源分别规定 title/name 的优先级。
3. **仅稳定 id**：避免把正文带进索引标题，但可读性最差。

## 3. UMP 必填创建时刻

官方 schema 要求 `time.created` 是 RFC 3339。M4 的许多记录没有创建时刻，
Prompt 日期也不能补成午夜。

推荐有可信记录创建时刻就使用它；否则填**目标迁移创建时刻**并明确标注含义。
这是目标记录时间，不是源事实时间；源 `created_at` 的缺失状态仍能回读恢复，
`observed_at` 等事实时间不补造。目标更新时保留原目标创建时刻。

另一条路径是：无源创建时刻的条目保持 unresolved，不输出 UMP。
不能用固定 epoch 或把日期补成午夜伪装成源时间。

## 4. 实现切片与验收

1. OKF：完整信封字段落位、scope 索引、追加迁移日志；未知字段保留，不伪造 verified。
   embedding 向量不进家，模型与维度保留，变化进入计划与回执。
2. UMP：只写 `*.ump.json` 数组，保留可逆 id 与不可信 owner 的边界；
   metadata 按 UMP 扩展槽承载，回读复核。`consent.redact` 不得当装饰字段，
   无法安全执行的要求不得静默忽略。
3. 将官方 schema 和 Apache-2.0 署名随 Writer 分发，测试/运行不依赖 `lab/upstream`。
4. CLI 注册 UMP；两种 Writer 产物有合成快照、官方 schema 校验、往返和历史更新测试。
   所有写入仍先计划、再显式审批；完整 workspace 验证通过才标记完成。

## 5. 完整目标格式的保护契约（已确认）

现有 `record_hash` 只覆盖回读后的 canonical。M5 新增的原生字段（例如 OKF 展示标题、
UMP 的目标创建时刻）以及共享 `index.md`/`log.md` 不一定进入 canonical。
仅靠原哈希，用户在目标侧改这些字段后，可能无法发现变更并在源更新时被覆盖。
这不是格式转换细节，而是 M3 的审批绑定与防覆盖约束必须延伸到的新边界。

推荐一次补齐：

1. `PriorWrite.target_hash`：记录上次实际写出的目标记录载荷哈希。
   OKF 对整份 Markdown 字节取哈希；UMP 对该条原生 JSON 做 JCS 后取哈希。
   下次计划和实际覆盖前都核对，原生字段变化同样 `target_modified`，不自动覆盖。
2. `TargetSpec.artifacts`：计划摘要绑定本次目标中将涉及的记录文件与共享索引/日志的路径、
   哈希和字节数。审批后这些文件变化或出现同名文件，先拒写，而不是重建覆盖。
   不收集正文，不建立额外状态账本，也不触碰未属于 Writer 的其他文件。
   共享文件只有确认是 Writer 管理的产物才允许重建；其他同名文件保持不写，报告待处理。
3. 计划和回执可带逐条 `target_map`：用 canonical/目标 JSON Pointer 和规则名解释类别、
   标题、迁移创建时刻及扩展槽落位，不内联值。预测中的同一映射参与摘要。
4. 引擎对有损转换以 Writer 的预计回读记录做历史相等判断，
   防止“向量明确移除后，下次又误认为源变化”的重复更新。

替代路径是保守降级：M5 的非空目标不更新，共享索引/日志不覆盖。
这不会丢用户修改，但不能满足完整的持续汇总与增量更新验收，不推荐。

v0 尚未发布；已直接修正涉及的 schema 正本、Rust 契约与合成向量，
不兼容旧回执，不改已确认的 dry-run、审批、删除防复活和无自动冲突裁决原则。

## 7. OKF 写入边界与原生规则

这一层负责把“批准了什么”与“实际落盘什么”对齐，不负责修改家模式的人工裁决原则。
按迁移流程分成四条规则，Reader 与 Writer 使用同一套 OKF 投影规则。

### 批准的是固定的目标路径

- Writer 构造时拒绝显式目标根链接，把已有祖先别名解析为真实位置，再保留不存在的后缀；
  操作系统的临时目录别名也在这一步处理。计划记录的是这个真实路径。
- apply 不重新批准一个经新链接解析出来的位置；构造出的路径必须与计划字面路径相等。
- 每次读写检查目标根的全部祖先、目标内中间目录和最终文件。
  中间项必须是非链接目录，最终项必须是非链接普通文件，FIFO 等特殊文件直接拒绝。
  只有 `NotFound` 表示不存在，权限、不是目录、读取与枚举错误都传播为运行失败。
- 检查与实际打开、建目录或替换之间仍存在竞争窗口。这不是目录句柄级隔离，
  也不是跨进程锁；不能声称面对持续恶意换目录时完全不会越界。

### 用户文件与受管记录分开判断

- 没有历史时，同名普通用户文件逐条 `target_untracked`，不接管、不覆盖；
  其他合格记录仍可执行。共享索引或日志未受管时阻止本批对它们的重建。
- 明确声明受管却损坏的信封、身份与来源公式不一致的记录，在写入前失败；
  不把损坏伪装成缺失。身份仍使用现有 system/native ID 公式，不引入卫星 ID。
  块式与 flow YAML 的明确管理声明都不能因语法损坏退回普通文件；
  Writer 预检与 Reader 都拒绝来源、作者/时间或标签投影与扩展矛盾的信封。
- 有历史时，同名路径换成非受管文件属于 `target_modified`，不当作已经删除。

### 原生输出遵守目标格式

- frontmatter 结束符必须独占一行；字段内的 `---` 与合法缩进块不切断信封。
  扫描、更新、inspect 和 Markdown 回读使用同一 LF/CRLF 边界规则，正文原样保留。
- 人类作者投影为 `human:<id>`，已有前缀不重复；canonical 中的原始作者不变。
  Scan/Import 不捏造内容作者。只有作者与修改时间都可得时输出完整 `generated`；
  来源修改时间仍保存在 `sources.last_modified` 与 canonical 扩展。
- 根索引 frontmatter 只含 `okf_version`，受管标记放正文。日志按日期分组，
  最新日期与同日新事件在前，用 `+新增数 ~更新数`，不把迁移时刻伪装成来源时刻。
  重建日期顺序时保留历史组内的原始文字与空行，包括换行形式和最后一行无换行的情况。
  不兼容尚未发布的旧私有索引/日志形状；遇到它们不静默接管，需要人工检查。
- `target_map` 只声明实际存在的原生投影，不因缺失的修改时间虚报 `generated.at`。
  向量移除、来源 metadata、重嵌入计划和无模型调用的契约保持不变。

### 失败按已发生的副作用解释

- 审批与执行依据检查失败：说明尚未开始目标写入，修正依据后重新规划和批准。
- Writer 调用一旦开始：后续写入、输出证明、回读或回执验证失败，
  保守说明目标可能部分改变，没有可靠最终回执，要求人工检查目标与审批，不盲目重试。
- CLI 明确区分审批是否已保存与最终回执是否保存。保存审批不表示迁移完成，
  单文件原子替换不表示整批回滚。

对应回归入口是 `crates/cli/tests/okf_repairs.rs` 与更新的 `writers.rs`。
合成原生产物检查不依赖共用投影 helper 计算预期，格式往返本身不作为符合性证明。
跨进程锁、整批事务/恢复、断电持久性、完整跨目标中断组合和真实数据符合性本轮不实现。

## 8. 增量汇总的历史依据与 UMP 原生验证

所有来源、目标和阶段默认增量汇总。源为空或本轮缺席只记 `source_missing`，不清空目标；
读/解析故障拒绝，显式删除意图仍待人工裁决，不提供镜像同步或删除执行器。
计划摘要可带 `digest_inputs.previous_receipt_hash`，绑定实际读取的整份旧回执字节；
因此空轮次仍要携带的历史、共享证明及裁决也属于批准依据。旧条目必须关联唯一 target 声明。
无历史计划不带该字段，已有目标仍按未追踪保护处理，不声称完整防复活。

UMP 数组在原始解析时拒绝重复对象成员（含嵌套和转义同键），不先选择最后一个值。
官方 schema、安全数字及 id 唯一性校验之外，凡声明 `body.structured.mem_adaptor` 的条目都预检迁移扩展，
包括与本轮源无关的条目；普通外来合法 UMP 记录不要求桥接块，保持原生值，不自动接管。
损坏扩展通过普通错误返回，不 panic；正文哈希、来源派生身份、向量维度和原生投影均要一致。

回读核对实际 kind、scope/owner/private、consent、observed/valid time 和迁移 provenance 与扩展的规则，
不能仅把原始 canonical 副本读回来就宣称映射正确。未知或缺失类别采用明确的默认规则，
不把原始未知值带进公开报告。首次目标 created 和 created_origin 在更新时保留，
源后来补来的创建时刻继续留在扩展中，不要求两者相等；迁移时间在归一化 golden 前核对实际范围。

Writer 的批量 inspect/native hash 接口允许单阶段一次读取并索引数组；回读同样批量处理。
不跨批准、写入、回读或回执阶段缓存目标，不取消真实令牌、原生哈希或文件字节证明的重核。
v0 未发布：新增完整历史摘要输入及 `source_missing` 原因码，不兼容旧 `source_deleted` 回执。
