## 1. 必须解决的跨卫星共享产物问题

M5 的目标保护是一条迁移链：旧回执中的共享快照发生变化就不自动写入。
家模式有多条卫星链。A 汇总后，B 合法汇总会改变家里的 index/log；
下一次 A 不能把 B 的合法写入误报成用户篡改。UMP 数组也有同样边界。

推荐**从现有回执对账**，不新建状态账本：

- 每颗卫星仍使用自己的上一份回执，维护记录更新与删除防复活。
- 引擎另外接收同一目标的最近一次已完成、已验证回执，作为共享产物历史依据。
  必须核对目标位置、Writer、schema 与共享快照；找不到唯一可靠依据就保持 unresolved。
- 当前共享产物必须与最新依据一致，不接受“任意旧快照匹配”来放行用户回滚。
- 纯 no-op、被阻止或验证失败的运行不推进共享写入依据；不能把用户改过的快照
  写进一份 skipped 回执后，就将其洗成下一次允许覆盖的依据。
- 对账依据的引用和文件哈希进入计划与摘要，审批后变化同样拒写。
- 推论（#44 真实数据实测确认）：同一目标背靠背生成的多个计划，第一个批准 apply 推进共享产物
  依据后，其余计划的共享依据即漂移，apply 被拒（退 4）；多卫星依次汇入时应逐个
  plan → apply，不要批量生成后依次 apply。
- 新增 A → B → A 的验收：合法跨卫星更新可继续，用户修改索引/日志仍不能被覆盖，
  各卫星删除防复活与原生记录哈希保护保持独立。

备选是暂时只支持单卫星家，保持 M5 原契约；实现简单，但不能完成 DEC-19 的多源汇总目标。

## 2. 卫星身份

推荐家模式显式要求 `--satellite <id>`，采用安全的单路径段标识。
回执按 `.mem-adaptor/receipts/<id>/` 保存，计划按 `.mem-adaptor/plans/<id>/` 保存；
避免两个同平台导出共用一条链，也避免把私密源路径直接变成目录名。
卫星 ID 参与 canonical id 算法：已按 DEC-20 从两段更新为三段
`sha256(system ‖ 0x00 ‖ satellite_id ‖ 0x00 ‖ source_record_id)`，直迁的卫星段为空字符串。

备选是按源绝对路径哈希自动分链，无需参数，但导出路径改变时会变成新卫星，
无法自动延续旧链。源移动不在本次中自动猜测或迁移历史。

## 3. 基础实现

- `init <home>`：明确告知家与回执属于敏感数据；询问密钥 pass/block，非交互显式
  使用默认 pass 并记录来源；创建受管 OKF 骨架与 `.mem-adaptor/config.toml`。
  已有配置/索引/日志不覆盖，不替用户 Git 初始化。
- 直迁读取用户级配置；首次交互选择策略后持久化。测试设置隔离配置目录，
  不修改用户真实配置。命令行显式策略覆盖配置，并在报告标明来源。
- 家模式从家配置确定 Writer 与策略，按卫星选择历史回执，报告留在控制目录；
  `.mem-adaptor/` 仍不会成为 Markdown 记忆源。
- `apply` 展示计划摘要与未写条目，保留显式确认；非交互不等待输入。
  裁决不得绕过密钥 block、禁用 consent 或未经处理的 redact，不允许借确认覆盖被改目标。
  新裁决会改变计划时必须重新出计划与审批，不修改已经批准的报告。
- 拟定退出码：0 完整成功，3 有 rejected/unresolved 或验证不符，
  4 审批/源/目标快照不一致，1 输入/schema/I/O 错误，2 CLI 用法错误。
  omitted（重复、已迁移、目标删除）不是失败。
- 用合成 fixture 覆盖配置、策略优先级、回执选择、跨卫星共享保护与各退出码，
  并用 tuistory 验证 init/交互 apply。最后运行全 workspace 验证。

待用户恢复 M6 后扩展报告契约并实施；不把 PII 检测或 M7 真数据验收提前冒充完成。
