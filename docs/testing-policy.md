# 测试规范：失败处理、边界与验收

本文件规定修改迁移链路时必须怎样处理和验证失败，由 [AGENTS.md](../AGENTS.md) 引用。
它是长期行为与测试约定，不是任务状态、测试执行日志或已实现能力清单。
任务状态与验收结果仍放 GitHub Issue/PR。

**“必须这样表现”不等于“当前已经做到”。** 现有合成测试只证明其实际断言的范围；
新增要求的实现缺口需在相关任务中核对，不因文档写入而视为解决。
本规范不授权批量修改代码、实现恢复系统或恢复 M6。

## 1. 统一失败处理原则

1. **依据不足，不猜测执行。** 计划、批准或本次依赖的历史依据缺失、失效或不一致，
   拒绝相关写入；不能偷偷按首次迁移执行，也不能自动改成新的批准。
2. **区分记录处置与运行失败。** 某条被拒绝、转换或跳过，可以不影响其他合格记录，
   但必须逐条报告。无法可靠解析文件、建立清单或验证执行依据时，不能假装只跳过一条。
3. **不混淆成功。** 命令完成、记录写入、回读一致、回执保存是不同事实。
   不能仅凭零退出码或 Writer 返回成功，就宣布所有源记录已完整迁移。
4. **按副作用说明结果。** 写入前失败与已开始写入后的失败必须区分；
   无法确认时报告可能部分完成或结果不确定，不宣称目标未变或已回滚。
5. **不盲目恢复。** 没有明确且经验证的恢复契约，不自动重试写入、
   覆盖/删除已有报告、重建历史依据或清理可能有价值的目标内容。
6. **明确能力边界。** 没有事务、锁、资源配额或完整检测，就不能声称拥有这些保证。
   高级能力可以另行实施，相关风险不能从交付说明中消失。

普通输入、文件系统与适配器运行错误通过 `Result` 传播；
关键边界添加阶段与操作上下文，CLI（Command-Line Interface，命令行入口）统一呈现。
不为每一种操作系统错误重复写恢复逻辑，不捕获后静默继续；
意外 panic 是缺陷，不作为正常失败处理通过验收。

## 2. 测试必须核对的四个方面

每个失败测试按适用范围检查：

| 方面 | 应检查什么 |
|---|---|
| 返回结果 | 是否属于预期拒绝/失败，普通故障是否通过错误返回而非 panic |
| 目标副作用 | 实际文件集合与字节、被保护的用户文件、临时文件与越界写入 |
| 迁移凭据 | 计划、审批、回执是否存在、有效且如实描述结果，历史依据是否被保留 |
| 用户输出 | 失败阶段、原因、目标状态与可行下一步；stdout、stderr、日志和报告不泄露敏感值 |

失败提示至少回答：“哪一步失败、为什么、目标可能怎样、下一步是什么”。
下一步可以是修正输入、恢复权限、重新规划，或检查目标并等待人工处理；
不能在安全重试尚未证明时泛泛建议“重试即可”。
本规范不新增报告字段或错误码；若需要结构化契约，另行确认并同步 schema。

### 目标状态的判定

- **尚未开始写入**：通过调用边界和目标快照证明，目标文件集合与字节应不变。
  临时解压文件、报告或审批文件可能已创建，不能扩大成“没有任何磁盘写入”。
- **已开始写入，执行失败**：核对哪些产物实际改变；不能假定跨文件或跨目标回滚。
  无法确定完整范围时，保守报告可能部分完成。
- **已写入但验证/回执失败**：不宣称完整成功，不生成伪造的 verified 历史依据。
  无回执时不能把失败执行自动当作下一次可靠的历史基线。

测试中的快照和故障注入只是证据手段，不表示产品已实现快照治理或恢复账本。

## 3. 重要场景与测试方法

以下是相关任务必须核对的行为要求，不是“这些测试现在全部存在”。
本轮未触及的场景不要求顺手全部实现；触及的关键缺口必须修复或由用户明确接受限制。

### A. 源加载、输入和环境

| 场景 | 预期行为 | 测试方法 |
|---|---|---|
| 空源、只有登记文件、无人认领文件 | 报告区分真实空记录、只登记与未识别，不把未认领文件假装解析成功 | 三种最小合成目录，检查清单、计数与目标不变 |
| 同一文件被多个 Reader 认领 | 拒绝，不自行选择一个 Reader | 两个测试 Reader 认领同一文件，断言错误且未调用写入 |
| ZIP 损坏或压缩方式不支持 | 源加载失败，不漏读后继续迁移 | 小型损坏/不支持的样本，检查普通错误返回、CLI 非零结果及目标不变 |
| ZIP 路径穿越、重复路径、符号链接 | 整包安全预检拒绝；预检通过前不写解压内容，不越界写入 | 合法条目后放危险条目，检查提取目录为空及外部 sentinel 未变 |
| 临时目录、源读取失败或权限不足 | 指明失败操作，不静默跳过源文件；写入前失败不改目标 | 隔离路径或确定性 I/O 故障注入，不依赖真实系统资源耗尽 |
| JSON/YAML 结构严重损坏 | 终止当前计划生成，不能输出被误认为完整的清单 | 被 Reader 认领的坏文件与好文件混合，检查错误及无目标写入 |
| 已知来源的 JSON 语法/外壳损坏 | 识别与有效性分开；独有文件名或同目录来源证据已确认的文件不能因解析失败退为无人认领 | 同名共享文件配来源标记，混合好坏文件检查 CLI 类别、目标字节、无成功计划与私密输出 |
| Markdown 空/注释 metadata、未闭合 frontmatter | 空/注释的闭合块视为无 metadata、保留正文；未闭合全文作正文并报 `frontmatter_unclosed`；闭合坏 YAML 仍失败 | 本地 Markdown 与 Claude memory 文件分别检查原文字节、分类和异常位置 |
| 允许容错的 Prompt 坏行 | 仅按该 Reader 已确认规则报告行级异常，区分严重解析失败 | 好坏行混合，检查异常位置、保留的合格记录和无敏感回显 |

“十条有一条不合格”是否继续取决于问题类型：
合法记录的业务拒绝与文件无法可靠解析不是同一情况。
扩大容错范围必须明确确认，不能仅为让测试通过而吞掉错误。

### B. 校验、审批和历史依据

| 场景 | 预期行为 | 测试方法 |
|---|---|---|
| Reader 身份、正文哈希、向量维度错误，或 metadata 整数不安全 | 在相关写入前拒绝，不舍入、猜身份或修造数据 | 合成 Reader 或源 metadata 注入，检查错误及无 Writer 写入 |
| 没有明确批准、摘要不匹配、批准后源或目标变化 | 不按旧计划写入；需要重新规划和批准 | 生成计划后分别改源正文/metadata、目标记录/索引/日志，核对快照 |
| 计划报告缺失或损坏 | 无可核对计划时停止，不自动重新生成并执行 | 执行前移除测试计划或写入坏 JSON，检查非零退出及目标不变 |
| 明确指定的旧回执缺失、损坏或属于其他源/目标 | 停止依赖该历史的执行，不退化成首次迁移 | 测试回执不存在、结构错误或关联不匹配，检查拒绝 |
| 未提供旧回执 | 不声称完整防复活；已有目标无可靠依据时不自动覆盖 | 有/无历史两组输入，分别检查删除保护与未追踪目标的处置 |
| 目标被删除、源暂时缺失或某轮没有可写记录 | 提供有效历史时不复活；下一轮仍保留相关历史依据 | 至少连续两轮，手动删除测试目标或移除测试源后再迁移 |
| 同正文但 scope/consent 不同，或重复代表后来更新 | 不因正文相同就丢掉不同语义或别名旧内容 | 多条合成记录、多轮变更，核对目标正文、身份和自身/代表历史 |

计划文件的路径只是定位方式；关键是执行持有并核对的有效计划内容。
若进程已读取有效计划，之后文件路径被删除，与“根本没有读到计划”不是同一个测试。
不得把缺少无关人工导读文档当成缺少机器执行依据。

没有旧回执时，空目标不能证明“从未写过”，也可能是“写过后被删除”。
当前不得声称能可靠区分二者。历史必需的增量模式与首次模式如何区分，
需在相应配置/交互任务中确定并验证，不在本规范中假装已实现。

### C. 逐条处置与字段保留

| 场景 | 预期行为 | 测试方法 |
|---|---|---|
| 某条禁止导出、删除意图或记忆禁用 | 按契约拒绝或待决策，不静默导出/执行删除；其他合格记录可继续 | 混合合格与受限记录，检查逐条处置和实际目标 |
| 密钥在正文、metadata 键/值、路径或身份中 | 检测与处置符合策略；报告与错误不泄露值；敏感身份不被改写 | 合成假密钥覆盖 pass/block/allowlist，检查输出及实际写入 |
| 未知 metadata、缺失时间或来源 | 保留或明确报告未承载，不编造；目标补迁移时间时标注来源 | 源与目标原生字段逐项对照，检查映射和时间来源 |
| 显式保护类别类型损坏、可选正文类型损坏 | 非字符串类别拒绝并提示修复，不能用另一层字段降级；Claude legacy/prompt 正文区分不存在、空字符串和错误类型 | 混合输入失败前目标快照不变；未知字符串类别仍保留并报告 |
| 目标不支持向量或要求未实现的脱敏 | 明确变换/损失或拒绝；保留已有重嵌入计划，不静默重嵌入 | 比较预计记录、原生产物及回读结果，检查 plan 与实际一致 |

密钥检测的 pass 策略允许命中内容原样写入目标；
“报告脱敏”不能被测试或说明误写成“目标没有敏感信息”。
本规范不改变默认策略、自动裁决或不静默重嵌入等既定设计。

### D. 写入、验证和回执保存

| 场景 | 预期行为 | 测试方法 |
|---|---|---|
| 无关用户记录/索引/日志，或受管记录损坏 | 不擅自接管；明确受管却损坏的记录写前拒绝 | 放入 sentinel、相似文件名和坏信封，检查字节与预检结果 |
| 目标符号链接或批准后目标再次变化 | 拒绝相关读写；不借链接越界，不覆盖未经批准的新字节 | 隔离目录中创建链接或在检查点修改目标，核对外部文件 |
| 写入调用失败、磁盘满等 I/O 故障 | 停止继续推进，不声称完整成功；根据实际副作用报告 | 在首次持久化前和一次持久化后分别注入失败，检查所有目标文件与输出 |
| 一个记忆文件成功，后续索引/日志或其他目标失败 | 明确可能部分完成，不宣称跨文件/跨目标回滚 | 在两个操作之间注入失败，检查成功部分仍可能存在及失败部分 |
| 回读差异、无法回读或输出被其他程序修改 | 差异/错误与 verified 区分；后来编辑不能成为本次输出证明 | 写后/回读后注入变更或错误，核对原生产物及回执依据 |
| 目标写入成功，但最终回执写盘失败 | 命令失败，明确目标可能已变，不能声称历史已保存或安全重试 | 在 `engine.apply` 返回后、保存回执时制造路径/I/O 失败，检查目标、报告文件与输出 |
| 重试时审批/回执输出已存在 | 不自动删除或覆盖文件，不因再次批准就绕过历史检查 | 第二次执行同一输出路径，核对报告原字节；恢复流程须另行确认 |

没有成功回执不代表“目标从未写入”；失败时可能留下审批文件、
无效或不完整的报告文件。检查其实际存在性与有效性，不一律断言所有报告都不存在。
单文件原子替换也不等于报告保存原子、整体事务或断电后持久性保证。

## 4. 统一的测试方法

### 先写预期，再写断言

每个用例说明：前提、操作/注入点、预计返回、预计目标状态、
预计凭据与提示、哪些内容不应发生。测试函数说明它验证的行为或回归。
不要从当前错误字符串倒推产品应有行为，也不要只断言 `is_err()`。

### 观察实际副作用

- 调用前保存临时目标的文件集合和原始字节，调用后对照；
  目标不存在、为空与已有文件三种前提按风险选择。
- 拒绝写入时，用测试 Writer 调用计数或明确的调用边界辅助证明未写，
  不能只检查一个预期文件没出现。
- 验证失败时检查实际原生产物，避免 Writer 写入与回读共享同一错误仍互相通过。
- 连续迁移的保护至少跨两轮验证；重复代表/空轮次等状态变化按场景增加轮次。

### 确定性故障注入

- 优先使用现有插件接口包装 Reader/Writer 或隔离文件系统条件制造指定失败。
  如果现有接口无法控制所需边界，另行确认最小测试接缝，不为测试添加大套生产抽象。
- 不用 `sleep` 碰运气制造竞态，指定在批准后、写入前、一次写入后或回读后触发。
- 权限测试要考虑高权限环境可能绕过权限位；采用可靠替代或注明跳过理由，
  不能把未触发故障的成功执行当成失败用例通过。
- 不撑满真实磁盘，不读取真实导出包，不改真实目标。崩溃测试只能终止测试自建子进程。
  进程终止能验证一部分中断行为，不能代替真实断电/硬件持久性证明。

### 安全、独立性和快照

- 合成输入中的假密钥不进入公开日志、Issue、PR 或报告；检查所有输出通道。
  测试临时目标在 pass 策略下可以包含该合成值，不以此误报检测缺陷。
- 单元与集成测试可以 import 被测实现；独立 conformance（符合性验证）执行器不可以。
  它从 schema 和产物独立验证，不以实现返回的“verified”自证。
- 黄金快照只规范化明确的动态字段；不得为了通过测试直接重录，
  必须通读差异并确认语义变化，不能规范化掉错误、遗漏或用户改动。

## 5. 验证范围与现有入口

先跑最快且直接相关的测试；行为/契约变化再扩大到受影响集成测试与 workspace。
不默认运行真实 API、真实导出或昂贵验证；这些需要单独授权并串行执行。
只改文档时通读正文、检查链接/代码块和 `git diff --check`，不声称因此验证了运行行为。

现有验证命令：

```sh
cargo test -p mem-adaptor-core --offline
cargo test -p mem-adaptor-cli --test migration --offline
cargo test -p mem-adaptor-cli --test writers --offline
cargo test -p mem-adaptor-cli --test review_regressions --offline
cargo test --workspace --offline
cargo build --workspace --offline
cargo clippy --workspace --all-targets --offline -- -D warnings
cargo fmt --all -- --check
git diff --check
```

部分现有测试可作为阅读与扩展入口，不能替代对本规范的逐条核对：

| 入口 | 已有断言的范围 |
|---|---|
| `crates/core/src/source.rs` 的 `full_archive_is_validated_before_any_extraction` | 危险 ZIP 的整包预检早于提取 |
| `crates/cli/tests/migration.rs` 的 `plan_leaves_existing_target_bytes_unchanged` | 计划不改变已有目标字节 |
| 同文件的 `changed_source_is_refused_before_target_write` | 源变化拒写，无目标与成功回执 |
| 同文件的 `noninteractive_apply_requires_explicit_approval` | 非交互未确认不写目标或审批文件 |
| `crates/cli/tests/review_regressions.rs` 的 `nested_secret_keys_are_detected_in_every_policy_without_leaking_report_paths` | metadata 键检测、策略与报告不泄露原键 |
| `crates/cli/tests/writers.rs` 的 `writer_output_proofs_reject_changes_before_write_after_write_and_after_read_back` | 写前/写后/回读后竞态被拒绝；后两类目标已可能更新 |

完整的环境故障提示、写一半恢复、
回执保存失败的统一提示与安全重试等，本规范不宣称已经覆盖。
ZIP 配额、锁、跨文件/跨目标事务、PII 检测、向量检索质量与真实导出验收，
需在对应任务验证；没有实现时只能明确限制，不能打成“通过”。

## 6. 每轮交付的验收证据

Issue 验收条件应写成可观察行为，而不是“错误处理完善”。
Agent 对本轮相关要求逐条给出：预期行为、测试入口与关键断言、实际执行命令、
结果及剩余限制。实现正确、测试执行与用户接受风险是三项不同判断。

可使用以下精简格式放入 Issue/PR，不另建任务进度文件：

| 行为要求 | 证据/断言 | 实际运行结果 | 限制或待确认 |
|---|---|---|---|
| 源变化不按旧批准写入 | 目标快照不变、错误返回、无成功回执 | 填实际命令与结果 | 不据此声称目录是整体快照 |

未实现、未运行和未验证必须分开说明。关键条件未满足时，
修复或请用户明确接受降级，不把“后续实现”自动当成当前验收通过。
交付后按 [review-workflow.md](review-workflow.md) 停下等待人工 review，
不由测试通过自动进入下一任务。
